# Squishtech Playtests

The landing page for Squishtech Industries Publishing's closed playtests. Testers enter a personal access code and
download any playtest they've been given. After that, each game updates itself through its own relay. The site is
static (GitHub Pages). Downloads go through a small Cloudflare Worker, the **portal**, which is the only thing that can
read the private build repositories.

```
 tester's browser ── POST /access {code} ──────────▶ portal Worker ── is the hash of this code in KV?
                  ── POST /download/offrecord ─────▶ portal Worker ── GitHub API, with its token
                  ◀── 303 to GitHub's short-lived link (expires in minutes); the zip comes from GitHub's storage
 the page itself  ── GET /catalog ─────────────────▶ newest build, version, size and notes of every game (public)
```

No key or token is ever on the page. Codes are per tester, revocable one at a time, and every download is logged.

## Layout

| Path | What it is |
| --- | --- |
| `index.html` | The landing page: access code, game cards, how it works, FAQ |
| `games/offrecord/` | Off Record's own page; `updates.js` holds its patch notes |
| `site/games.js` | The list of playtests: title, tagline, tags, card art, page |
| `site/config.js` | The portal's address and an optional contact email |
| `site/portal.js` | Access codes, the playtest dossiers, download buttons |
| `site/fx.js` | Motion: folds, scroll reveals, decoding headlines, the UTC clock |
| `site/hero3d.js` | The three.js hero: a paper iris folding open over the STI emblem (three@0.170.0 from jsDelivr) |
| `site/site.css` | The visual system: ink, paper, signal red; Jost (OFL) for display type |
| `site/brand/`, `site/fonts/` | Logo (light, ink), Squish head, Jost and its licence |
| `site/manifest.js` | Screenshot lists, generated by `tools/build_assets.py` |
| `assets/<slug>/` | Each game's screenshots (WebP, with `thumbs/`) |
| `assets/STI/` | A local drop folder, ignored by git |
| `portal/` | The Cloudflare Worker, its settings, and `testers.cmd` / `testers.ps1` for codes |

## Setting up the portal (once)

You need Node.js and a free Cloudflare account.

1. **A GitHub token.** In GitHub, go to Settings → Developer settings → Fine-grained tokens and generate a new token.
   - Resource owner: `csdavisbusiness`.
   - Repository access: **only** `offrecord-builds`, `StoneThrone-bug-reports`, `BoredToDepth-builds`, `NightHunt-builds` and `crowdcontrolboardgame-builds`.
   - Permissions: **Contents: Read-only**, nothing else.
2. In `portal/`:
   ```
   npx wrangler login
   npx wrangler kv namespace create CODES
   ```
   Paste the `id` it prints into `portal/wrangler.toml`.
3. Store the token as a secret, then deploy:
   ```
   npx wrangler secret put GITHUB_TOKEN
   npx wrangler deploy
   ```
   Deploying prints the Worker's address. Opening it should show `{"ok":true,...}`, and `<address>/catalog` should list every game's newest build.
4. Put that address in `site/config.js` as `portalUrl`. In `portal/wrangler.toml`, set `ALLOWED_ORIGINS` and `SITE_URL` to the site's address. Deploy again, then commit and push.

## Custom domain

- **The site.** Add a `CNAME` file holding the domain (for example `playtest.example.com`). At your DNS host, point a CNAME record for that name to `csdavisbusiness.github.io`. Then, in the repo's Settings → Pages, enter the domain and tick **Enforce HTTPS**.
- **The portal (optional).** If the domain's DNS is on Cloudflare, uncomment the `routes` line in `portal/wrangler.toml` (for example `portal.example.com`) and deploy. Cloudflare creates the record and certificate. Then update `portalUrl`.

## Testers

From `portal/`, in PowerShell:

```
.\testers.cmd add "Jane Doe"                       # every playtest
.\testers.cmd add "Jane Doe" offrecord,nighthunt   # just these
.\testers.cmd list
.\testers.cmd revoke "Jane Doe"
.\testers.cmd log                                  # who downloaded which build, last 90 days (UTC)
```

A code is shown once, when it's made, and only its SHA-256 is stored. If a code is lost, revoke it and add a new
one. To change someone's games, revoke their code and add a new one. A tester's saved code is re-checked every time
they visit, so a revoked code stops working at once.

## Adding a game or a build

- **A new build.** Nothing to do here. Each game's ship script publishes a release tagged `build-<n>` with one
  `.zip`, and the site picks it up within a minute. A release name like `v0.5.0, build 1121` also shows the version.
- **A new game.**
  1. Add it under `[vars.GAMES]` in `portal/wrangler.toml` (slug = builds repo) and deploy.
  2. Give the GitHub token access to that repo.
  3. Add the slug to `$known` in `portal/testers.ps1`.
  4. Add an entry to `site/games.js`.
  5. Add the slug to `GAMES` in `tools/build_assets.py`.
  6. Optionally, copy `games/offrecord/` as a starting page.
- **Screenshots.** Drop PNGs named `<slug>-NN-caption-words.png` into `assets/STI/`, then run
  `py tools\build_assets.py --import assets\STI --replace`. Each image is converted to WebP (at most 1920 px wide)
  with a thumbnail, and its caption comes from the file name. Without `--replace`, new images are added beside the
  old ones. A game's cover is `art` in `site/games.js`. Needs Pillow: `py -m pip install --user pillow`.
- **Patch notes** for Off Record go in `games/offrecord/updates.js`. Posts show newest first.
